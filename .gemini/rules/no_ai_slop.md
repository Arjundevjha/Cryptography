# Rule: Concise & Direct Technical Documentation (No AI Slop)

When creating or modifying documentation (such as `README.md`, docstrings, handoff documents, or commit messages):

1. **No Decorative Emojis**: Do not use emojis in section headers, bullet lists, or tables unless explicitly requested by the user.
2. **No Marketing Buzzwords or Hyperbole**: Avoid buzzwords like "Core Pillars", "Visual Metaphors", "State-of-the-Art", "Payload", "Seamless", or "Robust" unless describing exact technical symbols. Write concise, neutral technical facts.
3. **Human-Authored Style**: Keep text direct, clear, and grounded. Explain what the code or repository does, how to build/run it, and how to use it without dramatic summaries.
4. **Clean Markdown Structure**: Use simple headings (`#`, `##`), standard tables, and short code blocks. Avoid over-decorating lines with blockquotes, warning callouts, or bolding every first word in a bullet list.
